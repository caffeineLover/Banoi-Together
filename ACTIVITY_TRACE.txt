Additional static evidence
1. Quest state accessor 0x007BA3C0 reads quest+0x3C. The existing start
   routine writes 1 at 0x007BA6F4. The normal quest update 0x007BA860 tests
   state 1, invokes root-phase virtual +0x480, and, if it succeeds, writes
   2 at 0x007BA8AF and calls 0x007BBF50 at 0x007BA8B6.
2. Other native finish routes also write 2 then call 0x007BBF50, including
   0x007BA8D0, 0x007BA950, 0x007C50A0, 0x007C7490, 0x007CD9D0 and a
   route in 0x00816E79. Therefore a finish notification is not by itself
   proof of a local player's turn-in. Some routes can force/start/finish
   quests; the observer must never invoke them.
3. 0x007BBF50 calls GameDI virtual +0xBC8 at 0x007BBF66 (return RVA
   0x007BBF6C). Main GameDI vtable 0x00D01CE8 +0xBC8 is storage
   0x00D028B0, pointing to 0x00101A20. ABI observed from callers:
   void callback(void* game, void* quest). There is no actor argument.
4. RTTI verifies Quests::Quest at vtable 0x00EE5A08 and
   Quests::TalkPhase at main vtable 0x00F016B8. TalkPhase virtual +0x480
   is 0x00806620; +0x478 is 0x00806EA0. The check uses dialogue group,
   speaker and participant data. 0x00807B40 obtains the session's local
   context (session virtual +0x7B8), then 0x00115450 for a speaker, caching
   a smart-pointer pair at phase+0x140/+0x148. This is evidence of useful
   dialogue context, NOT yet proof that this context is the initiating
   player on both host and client. No completion send is authorized by it.
5. RTTI also identifies Quests::Replication::QuestState and
   QuestStateContainer at main vtables 0x00F10A08 and 0x00F11258.
   Existence of replicated state does not identify its initiator. Native
   state reconstruction/forced completion routes are reasons not to
   broadcast every observed active/finished state.
6. Actual exported quest-manager spelling is IGame::GetIQuestManager,
   not GetQuestManager (engine export RVA 0x0000A820 is a shared default
   implementation). A symbol name/default stub is insufficient evidence
   to call or hook it as the game's concrete manager. Further vtable tracing
   identifies GameDI +0x3D8 -> 0x00103270. It initializes the same quest
   singleton if necessary and returns 0x01326E10. This is the concrete
   manager accessor at the corresponding interface slot; the diagnostic
   does not need to hook or call it. That singleton's +0x88 mode
   is changed by the forced-finish route. Diagnostics record its raw value
   without inventing meanings for all enum values.

Acceptance target correction before extending the experiment
The existing start callback fires after phase startup. Startup can itself
activate other quests before the selected quest's callback. Capturing merely
the first scoped start could therefore select the wrong ID. The extension
must resolve the exact selected quest name BEFORE calling the button handler
and only capture a matching callback.
The stock mode-1 button handler calls 0x00137A60. It calls 0x00139BF0 with
this=0x01244BD8 and the selection string at screen+0x498. The returned record
selects a signed 16-bit index at -0xBE if byte -0x54 is nonzero, otherwise
-0xC0. Index bounds: dword -0x68. Row array pointer: -0x70; stride: 0x38.
The row's narrow ttl string is exactly the argument subsequently passed to
0x007CC890. The extension may call the read-only lookup and copy that name;
it must not call the unblocking/start routine itself. Reject unresolved or
nonmatching targets. The displayed title is still copied before the menu
closes using the existing verified IUIText::GetTextExplicit export.

Unchanged normal chat path and receive evidence
Call 0x0011E940 with the same local context and SayAll mode 0 as the stock
chat UI (0x0021E130). Do not prepend names. Stock remote producer 0x00105450
hands off to engine IGame::MsgSend. Its chat consumer 0x001054F0 takes the
network sender target, uses engine IGame::ReplGetTargetId and 0x0012E940,
then calls normal local chat delivery 0x001055F0. Further tracing identifies
the concrete GameDI incoming dispatcher at virtual +0x268 -> 0x00105330.
For packet byte 1 it advances data by one byte and decrements the byte count,
then tail-calls virtual +0xC48 at 0x0010539F. That slot is 0x001054F0.
The corresponding engine IGame base slot points to its default no-op at
0x00030420. This verifies the concrete dispatch-to-chat path; hooking the
default exported OnMsgReceived would miss it. Correct identity and remote
vanilla HUD behavior still require observations on the receiving PC.
